What Is Cursor?

Cursor is a code editor built by Anysphere, a small team that forked VS Code and rebuilt it with an AI assistant woven through the entire experience. Instead of an AI that sits in a sidebar extension, the AI is part of how the editor works — the keyboard shortcuts, the editing model, the context system.

It launched publicly in 2023 and grew fast through word of mouth. Developers would try it for a free week and switch. The combination of VS Code familiarity (your extensions, your settings, your keybindings all migrate) with a meaningfully better AI experience is a strong sell. It crossed a million users faster than most expect for a new editor.

Key Features

Cmd+K: Inline Edit

Select any block of code, hit Cmd+K (Ctrl+K on Windows), and type a natural language instruction. Cursor rewrites the selection. "Refactor this to use async/await." "Add error handling." "Make this function generic." It applies the change, shows you a diff, and you accept or reject. This is the feature that hooks most people. It's faster than writing the change yourself once you know what you want.

Cmd+L: Project Chat

Opens a chat panel that knows about your open files, your recent terminal output, and your recent edits. You can ask it to explain how something works, find where a function is called, debug an error from your logs, or make a change that affects multiple files at once. It can apply the changes directly rather than just describing them.

The multi-file edit capability is where Cursor pulls ahead of Copilot Chat. You can say "rename this variable everywhere it's used" or "add this new field to the schema and update all the places that use it" and Cursor will generate a diff across all affected files for your review.

Tab (Cursor Tab)

Cursor's version of inline autocomplete. It's similar to Copilot's autocomplete but with one difference: it predicts your next edit, not just your next characters. After you accept a suggestion, it predicts where you'll edit next based on the pattern. For repetitive refactors — renaming variables, updating a list of similar calls — it often chains suggestions so you can Tab through the whole task.

Codebase Indexing

Cursor indexes your whole repository so the AI can reference any file when answering questions, not just what's currently open. For larger projects this matters a lot — "how does authentication work in this app" becomes answerable because Cursor can look across all your auth-related files to give you a real answer.

Model Selection

Cursor runs Claude (Sonnet and Opus), GPT-4o, and several other models depending on your plan. On Pro, you get fast access to the best available models with generous usage limits. You can choose per-conversation which model to use — useful for switching between a faster model for quick questions and a more capable one for hard problems.

Is It Worth $20/Month?

If you write code for a living, probably yes. The Pro plan is $10 more than Copilot Individual but the jump in capability for whole-file and multi-file edits is meaningful. For developers doing active feature work — not just reading code — the time savings stack up quickly.

The free plan is a genuine free tier, not a bait-and-switch. 2,000 completions per month is enough for part-time coding. Try the free plan first, see if you reach the limits, then decide on Pro.

Cursor vs GitHub Copilot

The core difference: Copilot is an extension. Cursor is an editor. That sounds like a minor distinction but it shapes the whole experience.

Copilot is better for developers who want to stay in their existing VS Code or JetBrains setup without changing anything. It adds AI on top of your current workflow. Cursor replaces the workflow with one where AI is more central — faster to invoke, better at multi-file tasks, and more context-aware.

For most professional developers coding full-time, Cursor is the better tool. For developers who code part-time or who are deeply embedded in a JetBrains setup, Copilot is the easier choice.

Who Should Use Cursor?

Any developer who is already comfortable in VS Code and wants to see what the next level looks like. The migration takes about ten minutes and the learning curve is minimal since the underlying editor is familiar. Give it a week. If you find yourself hitting Cmd+K to do things you used to do manually, it's working. Most people who try it stay.
